## Proposed precedence matrix

1. Eligible OGL or precisely evidenced Savage Company exception; otherwise quarantine/exclude.
2. Same system (PF1), edition, publication, entity and variant. Missing legacy identity blocks automatic matching.
3. Verified applicable correction with authority/evidence and explicit field scope.
4. Approved source/field rule. None beyond the requested eligible d20PFSRD baseline is approved yet.
5. Fill missing validated values; never rank correctness by text length, field count or retrieval time.

| Evidence                                      | Baseline                        | Nonempty conflict                                             | Manual/verified field                                           |
| --------------------------------------------- | ------------------------------- | ------------------------------------------------------------- | --------------------------------------------------------------- |
| Eligible d20PFSRD record                      | Proposed initial baseline       | Review; preserve approved correction                          | Review                                                          |
| Eligible publisher errata, same work/version  | Retain original baseline        | Apply only reviewed field-scoped correction                   | Review                                                          |
| Eligible AoN / other secondary source         | Enrichment evidence only        | Review until authority rule approved                          | Review                                                          |
| Savage Company, exact publisher/work evidence | Exception, OGL status unchanged | Same authority/review rules                                   | Review                                                          |
| Unknown provenance                            | Quarantine                      | No contribution                                               | No contribution                                                 |
| Confirmed excluded contribution               | No retained content             | Reconstruct from eligible evidence or unavailable placeholder | Preserve user-authored material; remove copied excluded content |

## Runtime transition addendum: R17

`apps/web/src/content.ts:loadRuntimeContent` runs `completeCoreSpellProgression` over loaded classes, and `raceOptionsFromDataSet` combines favored-class bonuses by display name even while retaining separate race IDs. `buildSpellRegistry` indexes spells by display name. These are downstream rules, not source licensing evidence. They affect spell slots, race bonuses, and variant lookup.

The reviewed-release implementation rejects name collisions and conflicting normalized/pack copies before activation. It disables name-based spell enrichment and supplemental unreviewed armor, and keeps race bonuses within their canonical race identity. `completeCoreSpellProgression` remains unchanged: the proposed blanket bypass was removed after Astra review. Releases containing affected casting classes are blocked pending a verified, versioned runtime policy. Existing application behavior remains intact.

Recommendation: retain separately verified application automation with explicit provenance/ownership, avoid serializing inferred values as scraped facts, and do not activate a release that changes class behavior until the impacted classes and references pass comparison. Astra's completed addendum is `ASTRA-R17-REVIEW.md`; it requires specific user approval for verified progression rules and equivalences. `R17-IMPACT.json` identifies changed fields for Cleric, Druid, Paladin, Ranger and Sorcerer, plus eight race-name collision groups with different IDs. Staging has one character with a Druid level and one with a Sorcerer level (per-class counts, not necessarily distinct characters). Authoritative table comparison and the user decision remain pending. Current staging and production behavior have not changed.
