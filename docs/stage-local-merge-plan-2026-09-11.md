## Behavior that must be reconciled

1. **Preserve existing known/prepared spells during advancement.** At staging’s [`spellSeedPlans.ts:249`](https://github.com/Mathfinderd20/Mathfinder/blob/0f57c95253621c0c24ab4d65bd083846051afec8/apps/web/src/spellSeedPlans.ts#L249), a plan replaces the selection array for its class, mode, and level. An isolated execution confirmed that adding Burning Hands to a sorcerer with Magic Missile and Shield leaves only Burning Hands selected, although all three remain in the library. Preserve the local append behavior, case-insensitive deduplication for known/library entries, and intentional repeated preparations.
2. **Do not use preparation capacity as acquisition capacity.** Stage’s initial picker uses daily selection capacity and a four-suggestion shortlist. Its completeness helper accepts `min(capacity, offered suggestions)`; an isolated fixture with capacity six is marked complete after four choices. Keep the local starting-book allowance and all-cantrip handling, spontaneous known allowances, cleric domain choices, and automatic full-list libraries. Suggestions rank options; they must not define the complete legal list or required count.
3. **Separate book additions from preparation.** Stage’s library-only plans correctly preserve prepared spells. The local helper currently requires a prepared/known mode and limits additions using daily selection capacity, so it cannot simply consume those library-only plans. Give plans an explicit operation: acquire into library, add known spells, or add preparations. Validate the relevant allowance before application rather than silently dropping excess choices.
4. **Keep level-up changes scoped to the advanced class.** Stage builds ordinary seed groups for every caster, and excludes only the advanced spellbook class when it has free grants. Preserve our advanced-class filter. A Fighter or Wizard level must not incidentally rewrite another class’s known spells.
5. **Use one resolved casting policy.** Local `spellAccess` distinguishes full-list, spellbook, and limited-known casters. Stage additionally identifies books by a class-feature name and initial casters by a four-name allowlist. Consolidate on resolved class/archetype metadata; distinguish first entry into a casting class from a subsequent class level. Do not apply a wizard starting-book formula to every future book-based class without explicit rules support.
6. **Carry validation into the guides rather than retaining the old form gates.** Required favored-class details and two book choices must block their own step and appear in Review. Retain local whole-number HP checks, required feat/ability choices, accurate skill budgets, and fixes for selecting feat slots out of order. Do not restore staging’s module-level snapshot of class keys.
7. **Preserve optional preparation intent.** The merged creation flow should allow full-list and book casters to prepare an initial loadout in the magic step, while keeping that distinct from what they know or own. Preparing a cleric spell must not be treated as learning it or be required to populate the class library.

## Acceptance criteria

- Wizard creation: all permitted starting cantrips and the configured starting first-level book allowance; optional preparation does not add free acquisitions.
- Wizard advancement: two distinct new spells total, including a split across eligible levels; previously owned spells excluded; existing preparations unchanged. Test multiclass entry separately from an ordinary next Wizard level.
- Sorcerer and other limited-known casters: choices from the full legal list, existing known spells preserved, only newly available allowance consumed, no accidental changes when advancing another class.
- Cleric/Druid and delayed full-list casters: unlocked class spells available automatically, higher spell levels hidden until unlocked, explicit acquired extras retained, optional preparations separate, cleric domain handling retained.
- Favored bonuses: detailed choices persist through creation, advancement, Build editing, save/reload, and higher-level creation; changing class/bonus clears incompatible details; the skill option increases the usable budget correctly.
- Languages: duplicate prevention, restricted language handling, saved custom values retained, choosing later slots first, changing race/Intelligence, and Back/Continue all work without silent loss.
- Guides: all eight/five steps, incomplete-choice links, HP/skill/feat/ASI validation, class content loaded after module import, cancellation without save, and a campaign start above level 1 saved once after the final review.
- Existing characters: round-trip a multiclass saved build containing manual spell grants, preparations, languages, inventory, runtime state, and favored-class details. All unrelated data survives.
- Run typecheck, lint, all tests, the appropriately configured build, formatting/diff checks, and browser checks of creation and advancement. Database checks apply to the migration separately.
